# Feature map

Where each feature lives and what it owns. Boundaries per [ADR-003](adr-003-feature-boundaries.md): `app/**` = routing + thin route adapters, `components/**` = rendering, `lib/**` = domain services, `content/**` = large static datasets. All gameplay data is team-scoped (School → Class → Team → TeamMember) — see [ADR-001](adr-001-team-class-ownership.md) and [ADR-004](adr-004-per-student-class-membership.md).

This map records *stable* ownership, not file inventories — grep answers "what files exist"; this answers "whose feature is this, and which tables does it touch". Paths are relative to `apps/web/`. Refreshed during the `/update-github` docs pass.

## Core — identity, onboarding, teams

Clerk auth. `/` is marketing; `app/game` is the authenticated "door" (teachers → `/teacher`, everyone else → `/lab`).

- Routes: `app/(auth)`, `app/(public)`, `app/(onboarding)`, `app/game`, `api/onboarding`, `api/settings`, `api/team`, `api/class`
- UI: `components/auth`, `components/settings` · Domain: `lib/team`, `lib/onboarding`, `lib/clearance`, `lib/activity` (momentum)
- Models: `User`, `School`, `Class`, `ClassJoinRequest`, `Team`, `TeamMember`, `TeamInvite`, `TeamCurrency`, membership event logs, `ActivityFeed`

## Operations Hub & the daily loop

The ops tabset plus its deep-link routes under `app/(dashboard)/daily/*` (codex, expertise, failure, log).

- Routes: `app/(dashboard)/daily`, `api/ops`, `api/data-terminal`, `api/expertise`, `api/failure-log`, `api/project-log`
- UI: `components/ops` (incl. `data-terminal/`, `codex/`, `CodexTab`, `VegaStudyTab`) · Domain: `lib/ops`, `lib/data-terminal`, `lib/guides`, `lib/plot*`
- **Data Terminal** (`components/ops/data-terminal/`, `lib/data-terminal/` + `lib/data-terminal/runtime/`, `api/data-terminal/`): a three-lane analysis workbench over one `Dataset` spine — retired `Experiment`/`Measurement` (momentum + teacher reads repointed to `Dataset`; backfill in `backfill.ts`). The `Dataset` row holds typed `columns`/`rows` (jsonb) plus `charts`/`scripts`/`analyses`/`layouts` JSON columns, one per lane/feature. **Sheets** lane is recharts + closed-form trendlines, no Python (`sheets-chart.ts`, `trendline.ts`, `SheetsChart.tsx`). **Code** + **Lab** lanes run Python in a *sandboxed* Pyodide **Web Worker** (`runtime/pyodide.worker.ts`, `neutralize.ts` egress-kill, `protocol.ts` caps) whose wheels are served by a **same-origin authed proxy** `api/data-terminal/runtime/[...path]` from local `.pyodide-cache/` or R2 (chosen by `PYODIDE_SOURCE`); the main-thread hooks `useCodeRuntime`/`useLabRuntime` own the wall-clock timeout + `terminate()`. Lab's table-type→analysis gating and the nonlinear equation library are TS config registries (`analyses.ts` 26 analyses × 7 table types, `equations.ts` 15 models × 9 domains) mirroring the trusted Python source of truth `runtime/analysis-templates.mjs` (33 templates + fit engine). `code-bridge.ts` turns a chart/analysis spec into runnable matplotlib ("Open in Code mode"). Exported figures attach to a showcase via the new `figure` `AssetType` (`lib/showcase.ts`, `api/showcase/asset`; reuses the R2 upload flow, no new env). CSP gained `wasm-unsafe-eval`; `worker-src 'self'`; `connect-src` unchanged (the runtime is same-origin).
- **Field Codex**: lesson content lives in `lib/ops/codex/tracks/*`, authored by the `/codex-pipeline` workflow; registries generated by `codex:merge`, drift-checked by `codex:build --check` (gate 2).
- Models: `Dataset`, `ExpertiseExam`/`ExpertiseAttempt`, `ProjectLog*`, `CodexLessonProgress`, `CodexKpDay`, `TeamStudyPlan`, `VegaStudyMessage`

- UI: `components/fair`, `components/showcase` · Domain: `lib/fairs` (seeding is batched/single-flight), `lib/showcase*`

## PvP (Battle Arena)

Playable since v0.78.0. Server-authoritative combat; the client only renders returned state.

- Routes: `app/(dashboard)/pvp/leaderboard`, `app/(dashboard)/pvp/battle/[id]`, `api/pvp` (lobby payload, `refind`/`start_raid`, `[battleId]/action`, `leaderboard`)
- UI: `components/pvp` (`PvpFeature` IS the lobby — a Battle Arena gateway overlay, not a route)
- Domain: `lib/pvp/matchmaking` (class scope via `User.classId` through members, never the vestigial `Team.classId`), `lib/pvp/spell-catalog` (seeded by `prisma/seed-spells.mjs`), `lib/pvp/combat-engine`, `lib/pvp/spell-power`
- Art: `art/spellfx.py` → `public/sprites/spells` + `public/sprites/fx`, resolved via `getSpellIcon()`
- Models: `Spell`, `PvpRaid`, `PvpTrophies`, `PvpRaidQuota`, `TeamDailyTaskDay`

## Teacher tools

- Routes: `app/(teacher)/teacher`, `api/teacher`
- UI: `components/teacher` · Domain: `lib/teacher`
- Models: `TeacherFeedback`, plus read views over class/team/student data (see `lib/teacher/student-overview.ts`)

## Cross-cutting infrastructure

- **LLM**: `lib/ai`, `lib/anthropic.ts`, `lib/rate-limit.ts`; ledger models `AiOperation`, `AiUsage`. Cost policy: [runbooks/llm-cost](../runbooks/llm-cost.md). E2E must run with stub flags — see [runbooks/e2e](../runbooks/e2e.md).
- **Notifications**: `api/notifications`, `lib/notifications`; models `Notification*`.
- **Uploads**: `lib/uploads` (reservation-first — service owns the asset lifecycle, routes record intent), `lib/storage.ts`, S3; model `UploadedAsset`.
- **Data governance**: `api/data-requests`, `lib/data-requests`, `lib/retention`; models `DataRequest*`, `RetentionPolicy`, `DestructiveProposal`. Runbooks: [data-export-delete](../runbooks/data-export-delete.md), [restore](../runbooks/restore.md), [incident-response](../runbooks/incident-response.md).
- **Cron**: `api/cron`, `lib/cron`. **Client decoding**: API responses used by client state decode through `lib/api/client.ts` (ADR-003).
